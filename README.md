# X econ scraper

Читает публичные твиты небольшого списка X-аккаунтов раз в час через
headless-браузер и сохраняет новые твиты. Логин делается один раз вручную
локально, дальше сессия переиспользуется — сам скрипт никогда не вводит
логин/пароль автоматически.

## Важное предупреждение

Автоматизированное чтение X без официального API — это не то, что явно
разрешено пользовательским соглашением X. Риск — блокировка аккаунта,
под которым сохранена сессия. Поэтому:

- **используй отдельный "технический" X-аккаунт** для логина в этом скрипте,
  не тот, с которого ты постишь и который тебе дорог;
- не ставь интервал проверки чаще, чем реально нужно (раз в час более чем
  достаточно для 5–20 аккаунтов);
- если аккаунт всё же заблокируют — просто заведи новый и перелогинься
  (шаги ниже).

## Что понадобится

- Node.js 20+ установлен локально (для разового шага логина)
- Аккаунт на GitHub, куда положишь этот код в свой репозиторий
- Отдельный X-аккаунт для чтения (см. предупреждение выше)

## Шаг 1. Локальная установка

```bash
npm install
npx playwright install chromium
```

## Шаг 2. Разовый логин (локально, не в GitHub Actions)

```bash
npm run login
```

Откроется настоящее окно браузера — залогинься в нём в свой технический
X-аккаунт как обычно (с паролем, возможно с подтверждением по почте —
всё это ты проходишь руками). Когда увидишь свою ленту, вернись в
терминал и нажми Enter.

Появится файл `storageState.json` — это и есть твоя сохранённая сессия.
**Не коммить его в git** (он уже в `.gitignore`).

## Шаг 3. Список аккаунтов для мониторинга

Отредактируй `src/accounts.json` — впиши username (без `@`) тех, кого
хочешь читать. Начни с 5, потом просто добавишь строки в этот список.

## Шаг 4. Передать сессию в GitHub Actions

GitHub Actions не может открыть браузер у тебя на компьютере, поэтому
сессию нужно один раз передать через секрет репозитория:

```bash
base64 -i storageState.json | tr -d '\n' > storageState.b64.txt
```

(на Linux будет `base64 -w 0 storageState.json > storageState.b64.txt`)

Дальше в репозитории на GitHub:
`Settings → Secrets and variables → Actions → New repository secret`

- Имя: `X_STORAGE_STATE_B64`
- Значение: содержимое файла `storageState.b64.txt`

Файл `storageState.b64.txt` после этого удали — он больше не нужен, это
просто способ доставить куки в секрет.

## Шаг 5. Залить код в репозиторий и включить workflow

```bash
git init
git add .
git commit -m "init"
git branch -M main
git remote add origin <ссылка на твой пустой репозиторий на GitHub>
git push -u origin main
```

Workflow (`.github/workflows/scrape.yml`) подхватится автоматически —
он уже настроен на запуск раз в час по расписанию (`cron: "7 * * * *"`).

Проверить вручную, не дожидаясь часа: вкладка **Actions** в репозитории →
слева workflow **"Scrape X accounts"** → кнопка **Run workflow**.

## Как это работает дальше

- При каждом запуске скрипт заходит на страницы аккаунтов из
  `src/accounts.json`, сравнивает увиденные твиты с
  `data/state.json` (там хранится ID последнего виденного твита на
  каждый аккаунт) и находит новые.
- Новые твиты пишутся в `data/last-run-new-tweets.json` (виден в логе
  запуска, в артефакты между запусками не переносится — это просто для
  проверки, что скрипт реально работает).
- `data/state.json` коммитится обратно в репозиторий автоматически —
  так следующий запуск знает, что уже видел.
- Сессия (куки) хранится в GitHub Actions Cache и обновляется на
  каждом прогоне — логин заново не происходит.

## Если сессия "протухла" (перестало работать / X разлогинил)

Повтори шаги 2 и 4 — заново `npm run login`, заново закодировать в
base64, заново обновить секрет `X_STORAGE_STATE_B64`. Дальше, чтобы
Actions подхватил новую сессию, а не старую из кэша — удали существующие
кэши в `Settings → Actions → Caches` перед следующим запуском (иначе
кэш из прошлых прогонов будет иметь приоритет над секретом).
