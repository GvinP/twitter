# СмокБургер — демо Telegram Mini App

Статический лендинг бургерной в духе "Durger King": меню, корзина,
кнопка заказа. Написан на чистых HTML/CSS/JS, использует
[Telegram Web App JS SDK](https://core.telegram.org/bots/webapps) —
подхватывает тему Telegram, показывает `MainButton` внизу экрана и
отправляет заказ через `sendData`.

Открытый вне Telegram (просто в браузере), лендинг тоже работает —
показывает баннер-предупреждение и использует свою кнопку заказа внизу
вместо `MainButton`.

## Как задеплоить на GitHub Pages

1. В репозитории: **Settings → Pages → Source** — выбери **GitHub
   Actions** (не "Deploy from a branch").
2. Смержи эту ветку в `main` — сработает workflow
   `.github/workflows/deploy-miniapp.yml`, он собирает и публикует
   папку `miniapp/`. Можно также запустить его вручную во вкладке
   **Actions → Deploy Mini App to GitHub Pages → Run workflow**.
3. После первого успешного запуска ссылка появится в
   **Settings → Pages** и в самом workflow-run (что-то вроде
   `https://<username>.github.io/<repo>/`).

GitHub Pages отдаёт сайт по HTTPS "из коробки" — а Telegram требует
именно HTTPS-адрес для Mini App, так что для дальнейшей интеграции с
ботом больше ничего дополнительно поднимать не нужно.

## Как подключить к боту в Telegram

1. Создай бота (если ещё нет) через [@BotFather](https://t.me/BotFather):
   `/newbot`.
2. Там же: `/newapp` — привяжи Mini App к боту и укажи URL со
   Шага 3 выше (адрес GitHub Pages).
   Либо, если просто нужна кнопка меню у уже существующего бота:
   `/setmenubutton` → выбери бота → пришли текст кнопки → пришли тот
   же URL.
3. Открой бота в Telegram и нажми кнопку меню/приложения — откроется
   этот лендинг внутри Telegram.

## Что дальше, если хочется настоящих заказов

Сейчас при нажатии "Оформить" данные корзины уходят в чат с ботом через
`Telegram.WebApp.sendData(...)` — это штатный способ вернуть данные из
Mini App обратно в бота. Дальше это нужно принять на стороне бота:

- Простой вариант — бот на `node-telegram-bot-api` / `grammy` /
  `python-telegram-bot`, слушающий `web_app_data` в апдейтах, парсит
  JSON и отвечает пользователю ("Заказ принят, стоимость Х").
- Для настоящей оплаты — Telegram Payments API (`sendInvoice`) или
  внешний платёжный шлюз, вызываемый из бота после получения заказа.
- Отдельный бэкенд с БД нужен, только если заказы должны попадать не
  только в чат, а куда-то ещё (админка, CRM, кухня).

Для чисто демонстрационного лендинга (как сейчас) бэкенд не нужен —
GitHub Pages + бот в Telegram полностью достаточно.
